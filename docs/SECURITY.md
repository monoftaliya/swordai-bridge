# Модель безопасности

Документ описывает угрозы, от которых защищается SwordAI Bridge, и конкретные механизмы.
Проект предназначен для управления **собственным** устройством пользователя с его согласия;
вся модель построена так, чтобы это оставалось верным.

## Принципы (из задания) и как они выполнены

| Требование | Как реализовано |
|-----------|-----------------|
| Не выполнять команды от неизвестных источников | Каждая команда подписана ключом сервера (ECDSA P-256); устройство закрепляет открытый ключ и отвергает всё неподписанное/чужое. |
| Не принимать произвольный исполняемый код | Сервер присылает только одну из **фиксированных** инструкций с заранее описанными аргументами. Нет механизма «выполнить код». Аргументы строго валидируются (Pydantic `extra="forbid"` на сервере, строгий парсер на устройстве). |
| Не скрывать работу приложения | Постоянное уведомление сервиса, экранный индикатор активности (overlay), журнал действий в приложении, обычная иконка в лаунчере. Приложение себя не маскирует. |
| Не перехватывать пароли и конфиденциальные данные | Поля ввода пароля определяются и **блокируются** для чтения/ввода; коды (OTP) и номера карт в уведомлениях маскируются (`Redactor`). |
| Не обходить защиту банковских приложений | Список защищённых приложений (банки, менеджеры паролей, аутентификаторы) + эвристика; для них действия блокируются или всегда требуют подтверждения. |
| Не выполнять значимые действия без подтверждения | Режимы подтверждения; значимые действия (удаление, отправка, оплата, значимые слова) подтверждаются на телефоне. |
| Предусмотреть аварийную остановку | Кнопка в приложении, действие в уведомлении, плитка в шторке, экранная «СТОП», удалённая пауза с сервера. |
| Показывать, какие действия выполняются | Индикатор активности и журнал; подтверждения показывают суть действия. |
| Не обходить системные разрешения/блокировку экрана/защиту приложений | Используются только штатные механизмы Android (Accessibility, MediaProjection, SAF) с согласием пользователя; никаких эксплойтов/root. |
| Не заявлять, что интеграция с ChatGPT работает, пока не проверено | См. [TESTING.md](TESTING.md) и README — прямо указано, что не протестировано. |

## Угрозы и защита

### 1. Поддельные/чужие команды
**Угроза:** кто-то притворяется сервером или подменяет команду.
**Защита:** конверт команды содержит подпись ECDSA P-256 над детерминированной строкой
полезной нагрузки. Устройство проверяет подпись закреплённым открытым ключом (SPKI) и его
отпечатком. Полезная нагрузка включает `device_id` (адресата) и `v` (версию) — команда для
другого устройства или другой версии отвергается.

### 2. Повтор и переупорядочивание команд
**Угроза:** перехваченную команду повторяют позже.
**Защита:** `ReplayGuard` — уникальный `command_id`, **монотонный** номер `seq` на устройство,
а также `issued_at`/`expires_at` с учётом смещения часов (сервер сообщает своё время в
`welcome`). Просроченные и уже виденные команды не выполняются. Результаты кэшируются по
`command_id` — переотправка даёт доставку «не более одного раза».

### 3. Кража токена устройства
**Угроза:** утечка токена доступа устройства.
**Защита:** токен (`sdt_…`, 256 бит) на сервере хранится только как SHA-256-хеш; на устройстве —
в Android Keystore (AES-256-GCM). Отзыв устройства в админке немедленно закрывает его
WebSocket (код `4403`) и делает токен недействительным.

### 4. Несанкционированный доступ ChatGPT/клиента
**Угроза:** чужой MCP-клиент пытается управлять устройством.
**Защита:** OAuth 2.1 с динамической регистрацией клиентов (DCR), PKCE S256, страницей входа
и **согласия** (пароль администратора). Области доступа разделены: `device.read` (чтение) и
`device.control` (действия) — пользователь на странице согласия решает, давать ли управление.
Токены хранятся в виде хешей; refresh-токены ротируются, повторное использование
обнаруживается и фиксируется в аудите. `redirect_uri` ограничены списком хостов
(`chatgpt.com`, `chat.openai.com` + loopback для тестов).

### 5. Скрытое наблюдение/захват экрана
**Угроза:** незаметная съёмка экрана.
**Защита:** MediaProjection требует **системного согласия** на каждую сессию захвата
(диалог Android). Экранный индикатор активности показывает, что идёт работа. Приложение не
скрывает уведомление сервиса.

### 6. Кража секретов из полей и уведомлений
**Угроза:** чтение паролей, OTP, карт.
**Защита:** поля паролей распознаются и исключаются; `Redactor` маскирует коды и номера карт
в тексте уведомлений, прежде чем они куда-либо попадут.

### 7. Действия с необратимыми последствиями
**Угроза:** удаление, отправка сообщения, оплата «от имени» ИИ.
**Защита:** `SecurityPolicy` с режимами подтверждения. Значимые действия всегда требуют
подтверждения **на телефоне**. Для защищённых приложений (банки и т.п.) — отдельные правила.
Собственное приложение исключено из управления.

### 8. Непрерывная потеря контроля пользователем
**Угроза:** пользователь хочет немедленно всё остановить.
**Защита:** аварийная остановка из нескольких точек (приложение, уведомление, плитка шторки,
экранная «СТОП»), а также удалённая **пауза** с сервера. Важно: **возобновление** управления
возможно только с телефона — удалённо «разблокировать» нельзя.

## Криптография

- **Подпись команд:** ECDSA на кривой P-256 (`SHA256withECDSA`, DER, base64).
- **Ключ подписи сервера:** задаётся переменной `SIGNING_KEY` (PEM, base64-PEM или seed ≥ 32
  символов). Из seed ключ выводится детерминированно через HKDF-SHA256 (стабильный ключ между
  перезапусками и инстансами). Если ключ не задан — генерируется и хранится в БД.
- **Закрепление ключа (pinning):** устройство при пэйринге сохраняет открытый ключ и его
  отпечаток; дальше принимает подписи только этого ключа.
- **Токены:** устройства — SHA-256 (hash-at-rest); пароль админа — scrypt; сравнение —
  постоянное по времени (`consteq`).

## Хранение и удержание данных

- Скриншоты для просмотра человеком отдаются по **временным** ссылкам `/s/{token}` с коротким
  TTL (по умолчанию 300 c) и хранятся в памяти, не на диске.
- Журнал аудита чистится по расписанию (`AUDIT_RETENTION_DAYS`, по умолчанию 30 дней).
- В БД не хранятся «сырые» токены — только хеши.

---

## Что остаётся на ответственности пользователя

- Установить приложение **только на свой** телефон и выдавать разрешения осознанно.
- Хранить `ADMIN_PASSWORD` и `SIGNING_KEY` в секрете (переменные окружения хостинга).
- Использовать HTTPS/WSS в проде (MCP на не-HTTPS адресе, кроме localhost, отключается).
- Понимать, что надёжная «вечная» работа в фоне на Android не гарантируется (Doze,
  производители) — проект честно это оговаривает и предоставляет средства восстановления
  соединения, но не обещает абсолютной непрерывности.
