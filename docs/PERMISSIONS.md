# Разрешения Android

Здесь перечислены все разрешения и специальные доступы, которые использует приложение, и
зачем каждый нужен. Приложение запрашивает их осознанно и показывает статус в экране
«Разрешения».

## Разрешения в манифесте (`uses-permission`)

| Разрешение | Зачем | Когда спрашивается |
|-----------|-------|--------------------|
| `INTERNET` | Соединение с Cloud Bridge (WebSocket/REST). | Устанавливается автоматически. |
| `ACCESS_NETWORK_STATE` | Понимать смену сети, чтобы переподключаться. | Автоматически. |
| `FOREGROUND_SERVICE` | Постоянный сервис соединения с уведомлением. | Автоматически (Android 9+). |
| `FOREGROUND_SERVICE_SPECIAL_USE` | Тип foreground-сервиса: «постоянный канал управления по запросу пользователя». | Автоматически (Android 14+). |
| `FOREGROUND_SERVICE_MEDIA_PROJECTION` | Тип сервиса на время захвата экрана. | Автоматически (Android 14+). |
| `POST_NOTIFICATIONS` | Показывать уведомление сервиса и запросы подтверждения. | Диалог при первом запуске (Android 13+). |
| `RECEIVE_BOOT_COMPLETED` | Восстановить соединение после перезагрузки (если включён автозапуск). | Автоматически; работает, если пользователь включил опцию. |
| `WAKE_LOCK` | Режим «Высокая доступность» (по желанию) — удержание соединения. | Автоматически; активен только если включён режим. |
| `REQUEST_IGNORE_BATTERY_OPTIMIZATIONS` | Показать системный диалог исключения из оптимизации батареи. | По кнопке в приложении. |

> Намеренно **не** используется `QUERY_ALL_PACKAGES`. Вместо него — узкий блок `<queries>`
> (LAUNCHER и VIEW `*/*`), чтобы находить и открывать приложения без широкого доступа к списку
> установленных программ.

## Специальные доступы (выдаются вручную в настройках системы)

Эти доступы нельзя выдать обычным диалогом — пользователь включает их сам, и приложение ведёт
его в нужный экран настроек.

| Доступ | Зачем | Без него |
|--------|-------|----------|
| **Accessibility Service** (`AgentAccessibilityService`) | Чтение дерева интерфейса и жесты: нажатия, прокрутка, ввод текста, кнопки «Назад»/«Домой». Это основной механизм управления. | Нельзя читать экран и выполнять действия. |
| **Доступ к уведомлениям** (`NotificationCollector`, `BIND_NOTIFICATION_LISTENER_SERVICE`) | Инструмент `get_notifications`. | `get_notifications` недоступен; остальное работает. |
| **Захват экрана** (MediaProjection) | Инструмент `capture_screen` (скриншоты). Согласие запрашивается **каждую** сессию. | Нельзя делать скриншоты; `get_screen_info` (текстовое описание экрана) всё равно работает через Accessibility. |
| **Показ поверх других приложений** (overlay) | Экранный индикатор активности и кнопка «СТОП». | Индикатор/экранная кнопка недоступны; работа видна по уведомлению и журналу. |
| **Доступ к папкам** (SAF, по желанию) | Инструменты `search_files`/`open_file` — только в папках, которые пользователь явно разрешил, и только на чтение. | Поиск/открытие файлов недоступны. |
| **Исключение из оптимизации батареи** (по желанию) | Стабильность фонового соединения. | Соединение может чаще рваться в простое. |

## Разрешения компонентов (защита сервисов)

Сервисы объявлены с системными разрешениями-привязками, чтобы их мог запускать только
Android:
- `AgentAccessibilityService` — `BIND_ACCESSIBILITY_SERVICE`.
- `NotificationCollector` — `BIND_NOTIFICATION_LISTENER_SERVICE`.
- `StopTileService` — `BIND_QUICK_SETTINGS_TILE`.

`MainActivity` и `BootReceiver` экспортированы (того требует их роль: лаунчер и приём
системных бродкастов). `BridgeService`, `CaptureConsentActivity`, `ActionReceiver` —
`exported="false"`.

## Принцип минимальности

Приложение не просит ничего «про запас»: нет доступа к контактам, SMS, микрофону, камере,
точному местоположению, списку всех приложений. Всё, что есть, напрямую обслуживает описанные
инструменты. Подробнее о том, как эти доступы ограничены политикой безопасности, — в
[SECURITY.md](SECURITY.md).
