# Что протестировано, а что нет

Этот документ намеренно честный. Он отделяет то, что **действительно проверено
автоматическими тестами**, от того, что **требует вашего участия** (устройства, компьютера
для сборки, живых аккаунтов). Так вы не примете непроверенное за готовое.

---

## ✅ Проверено автоматически

### Сервер — 67 тестов (`pytest`)
Запуск: `cd server && pytest`

| Файл | Тестов | Покрывает |
|------|-------:|-----------|
| `tests/test_devices.py` | 21 | Пэйринг; WebSocket-рукопожатие; подпись и проверка команд; защита от повторов (id/seq/срок); доставка и **переотправка** результата при переподключении; подтверждения; **отзыв** устройства; **пауза**; события аварийной остановки; коды закрытия. |
| `tests/test_mcp.py` | 15 | MCP через **официальный клиент** (legacy и auto режимы); список из 15 инструментов; проверка **областей** доступа (`device.read`/`device.control`); результат-изображение + текст + временная ссылка; поведение при офлайн-устройстве и `pending`/`get_command_result`. |
| `tests/test_units.py` | 31 | Токены/хеши; ключ подписи (из PEM/base64/seed, HKDF); ограничение частоты; политика безопасности; редактирование секретов; разбор аргументов; **фикстура совместимости** (эталонная подписанная команда). |

Тесты проходят на **SQLite** в этой среде. В CI (`.github/workflows/server.yml`) настроена
**матрица** SQLite + **PostgreSQL 16** (сервис `postgres:16`, `TEST_DATABASE_URL`).

### Ядро Android — 17 тестов (Kotlin/JVM)
Чистое ядро не зависит от Android API, поэтому проверяется обычными JUnit-тестами:

| Файл | Покрывает |
|------|-----------|
| `CommandVerifierTest` | Приём корректной подписи; отказ при чужом ключе, подделке payload, неверном устройстве/версии, мусоре; **проверка подписи, сделанной Python-сервером**. |
| `SecurityCoreTest` | Блокировка защищённых приложений и полей пароля; подтверждение значимых действий; эскалация режимов подтверждения; маскирование кодов; правила защиты от повторов; значимые слова; бэкофф. |
| `ToolArgsTest` | Разбор последовательностей; разбор нормализованных сервером аргументов; отказ на неверных аргументах. |

### 🔗 Кросс-языковая совместимость (ключевой тест)
`CommandVerifierTest.verifiesSignatureMadeByPythonServer` берёт команду, **подписанную
Python-сервером** (фикстура `app/src/test/resources/interop/signed_command.json`, создаётся
`server/tools/make_interop_fixture.py`), и проверяет её кодом **Kotlin**. Это подтверждает, что
подпись сервера и проверка на устройстве совместимы по байтам.

### Проверка типов всего Android-кода
Весь набор исходников Android (56 файлов `.kt`) компилируется компилятором **Kotlin** против
API-заглушек Android/AndroidX/Compose/OkHttp — **0 ошибок, 0 предупреждений**, 504 класса.
Это проверяет корректность Kotlin и сигнатур вызовов, но **не** является полноценной сборкой
под Android (см. ниже).

### Сервер «вживую»
- **В процессе (ASGI):** полный цикл — пэйринг, WebSocket, подпись/повторы/переотправка,
  подтверждения, отзыв, пауза, MCP через официальный клиент, полный поток OAuth (DCR→PKCE→
  токен), области доступа, изображения и ссылки, ротация refresh-токена.
- **По реальному TCP:** HTTP — админ-панель, CLI `bridgectl`, MCP + OAuth. Проверено, что
  сервер поднимается и отвечает по сети.

## ❌ НЕ проверено (нужно ваше участие)

| Что | Почему не проверено здесь | Как проверить |
|-----|---------------------------|---------------|
| **Сборка APK** | В этой среде нет Android SDK/AGP и доступа к Maven/Google. | GitHub Actions (готовый workflow) или Android Studio — см. [BUILD_APK.md](BUILD_APK.md). |
| **Поведение на устройстве** | Нет реального Android: Accessibility, MediaProjection, реальные жесты, автозапуск, Doze. | Установить APK на свой телефон и пройти сценарии. |
| **Реальное подключение ChatGPT** | Нужен аккаунт/тариф с поддержкой пользовательских MCP-серверов. | По инструкции [CHATGPT.md](CHATGPT.md); учтите оговорку о тарифах. |
| **PostgreSQL в проде** | Матрица есть в CI, но реальный прод-деплой с Neon не выполнялся. | Задать `DATABASE_URL` на Neon и прогнать (см. [DEPLOY.md](DEPLOY.md)). |
| **WebSocket поверх `uvicorn+websockets`** | В тестах WS проверялся через ASGI напрямую (без реального сокет-транспорта и библиотеки `websockets`). | Поднять сервер и подключить телефон/эмулятор устройства. |
| **`tools/fake_device.py`** | Симулятор на `websockets` не запускался против живого WS. | Запустить против локального сервера. |

## Как всё перезапустить

```bash
# Сервер (SQLite)
cd server
pip install -r requirements.txt -r requirements-dev.txt
pytest

# Сервер против PostgreSQL
TEST_DATABASE_URL=postgresql://user:pass@localhost/bridge_test pytest

# Ядро Android в CI — задача Gradle:
#   ./gradlew :app:testDebugUnitTest
# (в этой среде ядро прогонялось отдельным JVM-скриптом, результат: 17/17).
```

## Итог
Серверная логика и криптографическое ядро протокола (включая совместимость Python↔Kotlin)
проверены тестами и «вживую». Платформенная часть Android написана и проходит проверку типов,
но её поведение на реальном устройстве, сборку APK и подключение к ChatGPT нужно проверить
вам — инструкции для этого есть в [BUILD_APK.md](BUILD_APK.md), [DEPLOY.md](DEPLOY.md) и
[CHATGPT.md](CHATGPT.md).
