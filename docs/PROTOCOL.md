# Протокол связи сервер ↔ устройство

Версия протокола: **1** (`PROTOCOL_VERSION = 1`). Транспорт: **WebSocket** (в проде —
WSS/TLS). Формат сообщений — JSON, одно сообщение на кадр. Этот документ описывает
аутентификацию, приветствие, команды с подписью, ответы устройства, события и коды закрытия.

---

## 1. Подключение и аутентификация

Устройство подключается к:

```
wss://<сервер>/ws/device
Authorization: Bearer sdt_<токен устройства>
```

Токен устройства (`sdt_…`, 256 бит) выдаётся при пэйринге (см. §6). На сервере хранится
только его SHA-256-хеш. Если токен отсутствует/неверен/отозван — соединение закрывается
соответствующим кодом (см. §7).

На одно устройство допускается **одно** активное соединение. При новом подключении старое
закрывается кодом `4000`.

---

## 2. Приветствие (сервер → устройство)

Сразу после успешной аутентификации сервер отправляет:

```json
{
  "type": "welcome",
  "protocol": 1,
  "server_version": "1.0.0",
  "server_time": 1730570000.123,
  "device_id": "dev_…",
  "device_name": "Pixel 8",
  "heartbeat_sec": 20,
  "key_fingerprint": "ABCD-1234-…",      // отпечаток открытого ключа подписи
  "integration": { … }                    // статус интеграции ChatGPT (для информации)
}
```

- `server_time` используется устройством для вычисления смещения часов (проверка сроков).
- `key_fingerprint` — отпечаток открытого ключа сервера (SHA-256, первые 16 байт, 8 групп по
  4 hex). Устройство сверяет его с **закреплённым** ключом; расхождение = отказ.

---

## 3. Heartbeat (устройство → сервер → устройство)

Поверх ping-фреймов OkHttp приложение шлёт прикладной heartbeat:

```json
{ "type": "ping", "t": 1730570000.0 }
```

Сервер отвечает:

```json
{ "type": "pong", "t": 1730570000.0, "server_time": 1730570001.0, "integration": { … } }
```

Если сервер не получает сообщений дольше таймаута простоя — соединение закрывается кодом
`4408` (idle).

---

## 4. Представление устройства (устройство → сервер)

После приветствия устройство отправляет:

```json
{
  "type": "hello",
  "protocol": 1,
  "app_version": "1.0.0",
  "android": 34,
  "capabilities": ["accessibility", "capture", "notifications", "files"]
}
```

И периодически — статус:

```json
{ "type": "status", "online": true, "capabilities": { … }, "battery": 72, "paused": false }
```

## 5. Команды и результаты

### 5.1. Команда (сервер → устройство)

Команда — это **конверт** с подписанной строкой полезной нагрузки:

```json
{
  "type": "command",
  "payload": "<строка JSON, см. ниже>",
  "sig": "<base64(ECDSA P-256 DER подпись байтов payload)>"
}
```

Поле `payload` — это **точная строка**, которая была подписана. Устройство проверяет подпись
именно над байтами этой строки (UTF-8), не над разобранным объектом. Сама строка —
детерминированный JSON (ключи отсортированы, без пробелов):

```json
{
  "v": 1,
  "command_id": "cmd_…",
  "device_id": "dev_…",
  "seq": 42,
  "tool": "get_screen_info",
  "args": { … },
  "issued_at": 1730570000.123,
  "expires_at": 1730570120.123,
  "origin": { "source": "chatgpt", "client": "ChatGPT" }
}
```

Поля:
| Поле | Смысл |
|------|-------|
| `v` | Версия протокола (должна совпадать). |
| `command_id` | Уникальный id команды (`cmd_…`). Используется для защиты от повторов и для `get_command_result`. |
| `device_id` | Адресат. Устройство отвергает команду с чужим id. |
| `seq` | Монотонный номер команды для устройства (защита от повторов/переупорядочивания). |
| `tool` | Имя инструмента (см. список в [CHATGPT.md](CHATGPT.md)). |
| `args` | Аргументы инструмента (строго проверены на сервере и на устройстве). |
| `issued_at` / `expires_at` | Время выпуска и срок. Просроченную команду устройство не выполняет. |
| `origin` | Информация об источнике (для журнала/подтверждения). |

> **Подпись (алгоритм):** закрытый ключ ECDSA P-256; `SHA256withECDSA`, подпись в формате DER,
> затем base64. На устройстве проверяется закреплённым открытым ключом (SPKI). См.
> [SECURITY.md](SECURITY.md).

### 5.2. Подтверждение приёма (устройство → сервер)

```json
{ "type": "ack", "command_id": "cmd_…" }
```

### 5.3. Прогресс (устройство → сервер, необязательно)

```json
{ "type": "progress", "command_id": "cmd_…", "step": 2, "of": 5, "note": "открываю приложение" }
```

### 5.4. Результат (устройство → сервер)

Успех:
```json
{ "type": "result", "command_id": "cmd_…", "ok": true, "result": { … } }
```

Ошибка/отказ:
```json
{ "type": "result", "command_id": "cmd_…", "ok": false,
  "error": { "code": "user_declined", "message": "Пользователь отклонил действие" } }
```

Сервер кэширует результат и отдаёт его MCP-вызову. Если соединение прервалось до доставки
результата, устройство **переотправляет** результат при переподключении (доставка «не более
одного раза» по `command_id` за счёт кэша результатов на устройстве).

## 6. Пэйринг (REST, до WebSocket)

Пэйринг выполняется по HTTPS, не по WebSocket:

1. Админ создаёт код в панели → код вида `XXXXX-XXXXX`, живёт 10 минут.
2. Устройство: `POST /api/v1/pair` с кодом и именем устройства → получает `sdt_…` токен,
   `device_id`, открытый ключ сервера и его отпечаток (закрепляются на устройстве).
3. Далее устройство подключается по WebSocket с этим токеном (§1).

Связанные эндпоинты: `GET /api/v1/device/me`, `POST /api/v1/device/unpair`.

---

## 7. Коды закрытия WebSocket

| Код | Константа | Когда |
|-----|-----------|-------|
| `4400` | `CLOSE_PROTOCOL` | Слишком много некорректных сообщений. |
| `4401` | `CLOSE_UNAUTHORIZED` | Нет/неверный токен устройства. |
| `4403` | `CLOSE_REVOKED` | Устройство отозвано администратором. |
| `4408` | `CLOSE_IDLE` | Нет heartbeat дольше таймаута. |
| `4429` | `CLOSE_TOO_MANY` | Превышен лимит подключений. |
| `4000` | — | Открыто новое соединение для того же устройства (старое закрывается). |
| `1009` | — | Сообщение превышает лимит размера (`MAX_WS_MESSAGE_BYTES`, по умолчанию 8 МБ). |

---

## 8. События (устройство → сервер)

Устройство может прислать событие, например аварийную остановку или паузу:

```json
{ "type": "event", "event": "emergency_stop" }
{ "type": "event", "event": "control_paused", "paused": true }
```

При `emergency_stop` / `control_paused` сервер отменяет незавершённые команды устройства.
Возобновление управления возможно только с телефона (см. [SECURITY.md](SECURITY.md)).

---

## 9. Ошибки протокола (сервер → устройство)

```json
{ "type": "error", "code": "bad_message", "message": "Malformed message" }
{ "type": "error", "code": "unknown_type", "message": "Unknown message type …" }
```

Эталонная реализация клиента протокола — `server/testkit/device_sim.py` (используется в
тестах). Независимый проверяльщик подписи на Kotlin — `android/.../core/protocol/CommandVerifier.kt`.
